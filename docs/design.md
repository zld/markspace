# Design notes

## Data flow

```
sample.Layer.Stream
      │  router: one chunk per layer, round robin
      ▼
stream.MuxSource ── framed [layer id][len][payload]
      │
      ▼
stream.Reader        bounded: token pool, queue+1 live chunks
      │
      ▼
stream.Demux         incremental, absolute per-layer offsets
      │  stream.Item
      ▼
stream.Fanout        one bounded queue per consumer, backpressure
      │
      ▼
pipeline.analyzer    incremental codec parser per layer
      │  []recovery.Unit + boundaries + truncation
      ▼
index.Validate ──► recovery.Recover ──► recovery.MergeResult
      │
      ├──► bitrate.Measure
      ├──► mp4meta.Encode/Decode (metadata cross-check)
      ├──► manifest.Build (quality, digest)
      └──► verify.VerifySources (invariants)
```

## Why the reader is multiplexed

The kernel has one bounded reader rather than one per layer, so the memory
bound is a single measurable quantity. Layer framing is five bytes of
envelope; the demux is incremental and rejects truncated records, unknown layer
ids and records beyond its bound.

## Recovery semantics

A keyframe is "verified" only when a validated index entry resolves onto an
intact keyframe unit discovered by the parser. Coverage is built only between
consecutive verified anchors:

- an intact interval becomes a `Segment`;
- an interval containing an unverified keyframe or an unrecoverable truncation
  becomes a `Gap` whose `Reason` is the kind of the failing claim;
- a gap's `Class` distinguishes recoverable resynchronization from
  unrecoverable loss.

This is why a corrupt index entry becomes a real gap instead of a silent
skip, and why a truncation never yields a segment that crosses it.

## Determinism

- Fixtures are generated by an xorshift64* PRNG seeded from `--seed` and the
  layer index; identical flags produce identical bytes.
- Fault lists are sorted by layer, byte offset, kind and detail.
- Manifest and verifier digests hash canonical JSON / evidence lines, so any
  change in coverage changes the digest.

One intentional exception: `chunk_bytes` is part of the run identity and
therefore of the manifest digest, while the recovered evidence (segments,
gaps, quality, verify digest) is independent of chunking. Tests assert both
properties.

## Deliberate limits

- Annex B has no explicit unit length, so a final unit that received its
  header is reported complete; only a bare trailing start code is provable
  truncation.
- AV1 parsing requires the `obu_has_size_field` bit, which the archive
  specification mandates; unsized OBUs are reported as header damage rather
  than guessed.
- The MP4 metadata document carries frame timing and sizes only. Media bytes
  remain in the elementary stream, which is the archival master.
