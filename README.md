# rtx — offline repair for weak-network RTP/CMAF captures

`rtx` is a small Go library plus CLI for regression-testing the real-time voice
media path offline. It parses recorded RTP traces and CMAF/fMP4 fragments,
restores weak-network defects (loss, reordering, 16- and 32-bit wrap, `mfhd`
gaps, rewinding `tfdt`, source switches), rebuilds a random-access index on one
exact media time base, and verifies the result with deterministic evidence.
The run is resumable and repeatable byte for byte.

Everything is pure local: no network, no external services, no graphical
dependency. All sample media is generated by Go code; no external assets are
used.

## Quick start

```sh
brew install ffmpeg && go mod download     # ffmpeg is optional (see below)
go mod tidy && go mod vendor && go build -o /tmp/rtx ./cmd/rtx
go test ./...
/tmp/rtx fixtures -work /tmp/rtx-fixtures
/tmp/rtx run -input /tmp/rtx-fixtures/good -cache /tmp/rtx-cache -checkpoint /tmp/good.json -out /tmp/rtx-good
/tmp/rtx run -input /tmp/rtx-fixtures/truncated -cache /tmp/rtx-cache -checkpoint /tmp/bad.json -out /tmp/rtx-bad; test $? -eq 2
/tmp/rtx run -input /tmp/rtx-fixtures/edge -cache /tmp/rtx-cache -checkpoint /tmp/edge.json -out /tmp/rtx-edge -stop-after 2; test $? -eq 75
/tmp/rtx run -input /tmp/rtx-fixtures/edge -cache /tmp/rtx-cache -checkpoint /tmp/edge.json -out /tmp/rtx-edge
```

Exit codes: `0` ok, `1` failure, `2` truncated input (with the first unreadable
offset), `64` usage, `75` interrupted (resumable).

### Toolchain note

`go.mod` pins `github.com/abema/go-mp4 v1.7.3` and
`github.com/pion/rtp v1.10.6`. That pion/rtp release declares `go 1.24.0`, so the
module's `go` directive is `1.24` even though the code targets the 1.23
language. With a stock Go 1.23.x install, `go build` will fetch the 1.24
toolchain automatically (`GOTOOLCHAIN=auto`, the default) or you can set
`GOTOOLCHAIN=go1.24.0` explicitly. The pinned versions are exact; `go.sum` and
`vendor/` are committed.

## What the run guarantees

A successful run prints, on stdout:

```
records=<n> cursor=<n> repeat_equal=1 resume=<0|1>
gap=<n> tfdt_rollback=<n> source_switch=<n>
rtp source=... packets=... gaps=... seq_wraps=... out_of_order=... ts_wrap=<0|1> span=...
frames=<n> pixel_mean=96.00 peak_dbfs=-6.02 av_sync_ms=0.00 frame_sha256=<64 hex>
evidence_check=1
index_sha256=<64 hex> media_sha256=<64 hex>
fragment_sha256[i]=<64 hex>        (one line per written fragment)
cache_hits=<n> cache_misses=<n>
run_ok=1
```

`repeat_equal=1` is not assumed: before it is printed, the pipeline re-derives
the timeline and index from the inputs and re-hashes them, and requires the
result to equal what was written to disk.

For the `edge` fixture the counters are `gap=1 tfdt_rollback=1 source_switch=1`
and the resumed run reports `resume=1`. A truncated fixture exits `2` and prints
`first_unreadable_offset=<n>`.

## Architecture

```
internal/model     integer-rational Rate/Time, exact rescale/compare, coded *Err
internal/rtp       trace parsing, sequence unwrap + reorder, explicit anchors
internal/cmaf      box parser (bounded lengths), fragment model, writer, manifest
internal/repair    per-source/track monotonic tfdt repair with byte-level evidence
internal/index     keyframe + sample-offset index with original↔repaired mapping
internal/cache     content-addressed store, re-verified on every hit
internal/pipeline  resumable run, checkpoints, artifact/report writers
internal/evidence  deterministic JPEG/PCM metrics
internal/fixtures  pure-Go generation of every scenario
cmd/rtx            terminal CLI
```

### One media time base, one error model

All timing uses `model.Rate` (an exact positive rational of ticks per second)
and `model.Time`. Rescaling and comparison never round: a value that does not
land exactly on the destination grid returns `model.ErrInexact`. The fixtures use
a 720000 Hz unified grid (`lcm(90000, 48000)`), so 90 kHz video and 48 kHz audio
land exactly.

Every failure is a `*model.Err` carrying a stable `Code`, the operation and,
where known, the byte offset and half-open media range. Repair violations also
name the source, fragment and track.

### RTP

Traces are newline-delimited JSON datagrams. `pion/rtp` parses each packet and
the declared `seq`/`timestamp`/`ssrc`/`payload_type` are cross-checked against
the datagram, so an edited capture fails instead of repairing silently.

`Reorder` unwraps 16-bit sequence numbers relative to the first recorded packet,
sorts, drops duplicates and records gaps. A jump of exactly half the sequence
space is rejected as ambiguous. Missing packets only produce gap records; no
media duration is invented for them.

`Mapping` converts RTP timestamps to media time only through explicit anchors
(`rtp_timestamp`, `wrap`, `media_ticks`, `clock_rate`). A source without an
anchor, anchors that disagree, a timestamp exactly half the 32-bit space from
the anchor, or an off-grid result are all coded errors.

### CMAF/fMP4

The parser reads the restricted profile the fixtures use: one `moof` + one
`mdat` per fragment, `tfdt` v0/v1, `trun` with per-sample duration/size/flags.
It records absolute offsets for every box, the `tfdt` field itself and every
sample, and rejects any box size that escapes the file with
`truncated_box` at the first unreadable offset. Fragment files are capped at
64 MiB.

A missing `mfhd` is represented as a nil sequence number; it neither invents a
sequence number nor closes an open gap.

### Repair

`tfdt` is made monotonic per source and track. A fragment whose `tfdt` rewinds is
raised to the track's previous decode end; the repair records source, fragment,
track, original value, repaired value, the `tfdt` field's byte offset, and the
source's explicit media offset. Source switches are placed by an explicit
`media_offset_ticks` per source, never inferred from fragment contents.

### Index

Every sample is indexed with its track time, media time, original (pre-repair)
media time, byte offset, size and enclosing `moof` offset. Keyframes are the
decode restart points; every audio sample is one by construction. `Seek` returns
the latest keyframe at or before a target (with an explicit `no_keyframe` failure
for targets before the first one).

### Cache

Keys bind the origin digest, the processing parameters (media rate, track ids,
repair on/off) and a format version. A hit is accepted only after re-verifying
the origin digest, the content digest and the size; anything else is reported as
a miss with a reason, invalidated, and recomputed.

### Checkpointing

The checkpoint binds the manifest digest, the full input digest (manifest plus
every fragment's bytes) and the parameter digest. Each fragment artifact is
written atomically; only then does the cursor advance and the checkpoint get
replaced atomically (temp file + fsync + rename + directory fsync). On resume the
recorded artifact digests are re-verified. A changed input is rejected rather
than duplicated, because the timeline and index are deterministic functions of
the whole input and are stored in the checkpoint.

### Evidence

Video is decoded offscreen with the standard library JPEG decoder (the fixtures
are all-intra MJPEG) and luma is averaged in integer/BT.601 space. Audio levels
are measured directly from 16-bit big-endian PCM. `pixel_mean`, `peak_dbfs` and
`av_sync_ms` therefore come from the same pure-Go path every time; FFmpeg is not
part of the canonical measurement, so the numbers cannot drift with its version.
FFmpeg 7.x/9.x is still useful to independently confirm the written artifacts
decode and seek:

```sh
cat /tmp/rtx-fixtures/good/cam-a-init.mp4 /tmp/rtx-good/*.m4s > /tmp/joined.mp4
ffprobe -hide_format -v error -show_entries stream=codec_name,width,height /tmp/joined.mp4
ffmpeg -hide_banner -i /tmp/joined.mp4 -vf signalstats,metadata=print:key=lavfi.signalstats.YAVG -f null -
```

## Fixtures

| name        | demonstrates                                                           |
|-------------|------------------------------------------------------------------------|
| `good`      | clean single source                                                    |
| `edge`      | `mfhd` gap + `tfdt` rollback + source switch, RTP loss/reorder/32-bit wrap |
| `gap`       | one skipped `mfhd` number                                              |
| `rollback`  | one rewinding `tfdt`                                                   |
| `switch`    | a two-source switch at an explicit media offset                        |
| `nomfhd`    | a fragment with no `mfhd` box                                          |
| `truncated` | final fragment cut mid-`mdat`; exits 2                                 |
| `badcache`  | clean media used by the cache-corruption test                          |
| `oversize`  | a fragment declaring more than 64 MiB                                  |
| `queue`     | more than 32 fragment records                                          |

## Limits

- Manifest paths are relative to the input directory; absolute paths and parent
  escapes are rejected.
- At most 32 fragment records per run, each at most 64 MiB.
- Only the restricted CMAF/fMP4 profile above and recorded RTP traces are
  accepted; no network input.
- Cached artifacts and every landed output are digest-verified.
