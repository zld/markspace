# mediarun

A deterministic Go processing kernel for archive/broadcast frame sequences and
their RTP audio. It validates checksummed frame records, repairs audio
ordering, conceals small losses, aligns audio to picture on one clock,
repackages into ISO-BMFF and writes a reviewable provenance manifest that
survives restarts.

Everything runs locally on macOS. Sample data is generated by the tool itself;
no external media files are required.

## Quick start

```sh
go mod tidy
go build ./...
go test ./...
go run ./cmd/mediarun --generate --out ./tmp/run --resume --verify
```

Healthy run (exit 0):

```
frames=32 audio_packets=64 segments=4
parse_errors=0 first_error_offset=-1 recovered_audio=0 recovered_video=0 dropped_audio=0
roundtrip_match=100%
keyframe_hit=100%
segment_sha256_count=4
segment_sha256_equal=1
idempotent=1
```

Damaged input (exit 2):

```sh
go run ./cmd/mediarun --generate --out ./tmp/bad --inject truncated,checksum --verify
```

```
parse_errors=2 first_error_offset=252 recovered_audio=0 recovered_video=1 dropped_audio=0
fault_summary=checksum_mismatch:1,truncated_record:1
fault stage=checksum kind=checksum_mismatch offset=252
fault stage=parse kind=truncated_record offset=3906
```

Exit codes: `0` success, `2` input damaged but a verifiable output was
produced, `1` configuration or internal error.

## Fault injection classes

`--inject` accepts a comma-separated subset of:

| class       | what it does                                                        |
|-------------|---------------------------------------------------------------------|
| `truncated` | cuts the stream inside a record; the scanner reports that offset     |
| `checksum`  | flips one payload byte; the digest fails at that record's offset     |
| `seqwrap`   | starts audio sequence/timestamp just below the 32-bit wrap           |
| `overflow`  | reverses a long packet run past the jitter window cap                |
| `gap`       | removes 3 packets (concealed) and 12 packets (fragment incomplete)   |
| `dupe`      | duplicates two packets                                               |
| `desync`    | delays audio by 100 ms (or `--audio-late-ms N`)                      |

Two fault classes propagate all the way through the pipeline and are covered
by tests: parse/checksum damage reaches sync and mux (output still verifies,
recovery counted), and audio gaps reach the segment manifests as `loss_gap`
plus `fragment_incomplete`.

## Architecture

```
frames.mfr ──parse/checksum──┐
                             ├── clock.Timeline ── syncer ── mp4mux ── index
audio.rtp ──rtp──jitter──recovery──┘                                   │
                                                                       └── provenance manifest
```

| package | responsibility |
|---|---|
| `internal/fault` | structured errors: stage, kind, input offset, track, record |
| `internal/clock` | tick domain, rate schedule, RTP wrap unwrapper |
| `internal/frames` | record decode, SHA-256 verify, resynchronising scanner |
| `internal/rtp` | pion/rtp sidecar parsing, extended sequence window |
| `internal/jitter` | order by extended sequence, dedupe, window cap, commit floor |
| `internal/recovery` | conceal small audio holes, flag large ones, never fabricate video |
| `internal/syncer` | place RTP on the timeline, detect drift and rate changes |
| `internal/mp4` | go-mp4 remux, one sample per record, byte-preserving |
| `internal/index` | keyframe/sample index; verifies offsets against the MP4 tables |
| `internal/pipeline` | stage orchestration, checkpoints, resume, verification |
| `internal/provenance` | deterministic JSON manifest, atomic writes |
| `internal/gen` | deterministic fixture generator |

## On-disk formats

### Frame container (`frames.mfr`)

```
magic   "MFR1"
version uint16 (1)
flags   uint16 (bit0 keyframe, bit1 end-of-stream)
track   uint8
stream  uint8
pts     uint64 (90 kHz)
dts     uint64 (90 kHz)
size    uint32 payload length (1..4 MiB)
payload [size]byte
digest  [32]byte SHA-256 over everything above in this record
```

Offsets are absolute file positions. A record that fails a length bound, the
digest or a timestamp check is reported at its own offset and the scanner
resynchronises on the next magic, so later records still surface. Memory use is
one record at a time, and the pipeline's planning pass keeps metadata only.

### RTP sidecar (`audio.rtp`)

```
magic "RTP1", count uint32, then count × (length uint32 + datagram bytes)
```

`audio.stats` records the declared stream origin (`base_rtp`) so a late audio
start is measured, not silently re-anchored to video.

## Guarantees

* **Input-offset traceability.** Every fault carries the byte offset of the
  record or packet that caused it; the manifest sorts them with byte-anchored
  faults first.
* **No fabricated picture.** Recovery inserts audio silence only. Video frames
  are dropped or kept whole, never synthesised.
* **Late packets cannot rewrite output.** Committed jitter data is immutable;
  late arrivals and duplicates are recorded with a reason and a source offset.
* **Idempotency.** Segment bytes depend only on input digests and the config
  hash. Re-running reproduces identical segment hashes and a byte-identical
  manifest; a changed config or input invalidates the checkpoint and
  recomputes.
* **Crash safety.** Every output (manifest, index, segment, checkpoint) is
  written to a sibling temp file, fsynced and renamed. A resume reuses a
  segment only when the checkpoint digest, keyframe index and sample-level
  roundtrip all agree; otherwise it rebuilds from the verified plan.
* **Bounded memory.** Resident memory tracks the jitter window and one
  segment's payloads, not the asset length. Record counts, payload sizes,
  index entries and timescales are all capped.

## Artifacts under `--out`

```
frames.mfr, audio.rtp, audio.stats   inputs (generated)
checkpoint.json                      stage completion + per-segment digests
segments/segment-NN.mp4              remuxed output
index/segment-NN.mp4.json            keyframe and per-sample source mapping
manifest.json                        reviewable provenance document
```

`manifest.json` contains input digests, a summary per stage (input/config/output
hash, counts, faults), per-segment hashes and verification counters, and the
exit-relevant metrics. It never records wall-clock time or map iteration order,
so two identical runs serialize identically.
