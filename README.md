# mediapipe

A local Go media-processing kernel for timestamped MP4/MOV batch delivery. It
scans containers into a digest-addressed index, plans shared keyframe-aligned
segment boundaries across representation layers, streams segment payloads with
atomic writes, records resumable checkpoints and provenance, and recovers
synthetic RTP packet loss.

Everything runs locally and in the terminal. Sample MP4/MOV files and RTP
sequences are generated by the code; nothing is downloaded and there are no
external services.

## Requirements

- Go 1.23 (tested on macOS/Darwin)
- `github.com/abema/go-mp4` v1.3.0 for box and track parsing
- `github.com/pion/rtp` v1.8.11 for RTP packets
- Python 3 only for the acceptance script's JSON assertions

```sh
go mod tidy
go build ./...
go test ./...
```

## Quick start

```sh
# Generate sample inputs (good, corrupt, rtp-loss) under ./tmp/samples
go run ./cmd/verify --generate ./tmp/samples

# Process the healthy samples
go run ./cmd/verify --input ./tmp/samples/good --segment 2s --bitrates 500k,1000k --report json

# Process the corrupt samples (classified failures, batch continues)
go run ./cmd/verify --input ./tmp/samples/corrupt --report json

# Interrupt after one committed segment, then resume
go run ./cmd/verify --input ./tmp/samples/good --segment 2s --bitrates 500k,1000k --interrupt-after 1
go run ./cmd/verify --input ./tmp/samples/good --segment 2s --bitrates 500k,1000k --resume --report json
```

`--work` selects the output root (defaults to `work` beside the input). Every
artifact (index, segments, checkpoint, manifest, provenance) lives below it,
keyed by input digest.

## Exit codes

| Code | Meaning |
|------|---------|
| 0 | success |
| 1 | invalid arguments |
| 2 | one or more inputs failed |
| 3 | internal error |
| 10 | interrupted after N segments (resume to finish) |

These are the codes the binary returns. **Note:** `go run` reports a non-zero
program exit as its own status `1`, so to observe codes 2/3/10 exactly, build
and run the binary:

```sh
go build -o ./verify ./cmd/verify
./verify --input ./tmp/samples/corrupt --report json   # exits 2
```

## Acceptance

`scripts/acceptance.sh` runs the full workflow and asserts every criterion:

```sh
bash scripts/acceptance.sh
```

It checks:

- good run: non-zero `segment_count`, stable `manifest_sha256`,
  `av_sync_error_ms <= 40`, `packet_recovery_rate` of 1.0 for complete
  sequences, finite non-negative `p95_latency_ms`, and layer boundary spread
  within one video frame;
- corrupt run: exit 2, per-file error categories, non-zero failure count;
- RTP burst loss: exit 0 with a below-unity recovery rate and a gap recorded
  in the manifest;
- interrupt: exit 10; resume: same segment count and `manifest_sha256` as an
  uninterrupted run, with no duplicate entries;
- input mutation: index digest and manifest digest change, stale checkpoint is
  discarded.

## Layout

| Path | Purpose |
|------|---------|
| `media/clock.go` | exact integer media time (ns) with 128-bit tick conversion |
| `media/errors.go` | shared classified error and issue model |
| `media/probe.go` | container/track probe with sample and keyframe timing |
| `index/scan.go` | build a versioned, canonically digested index |
| `index/store.go` | digest-keyed cache with atomic persistence |
| `pipeline/alignment.go` | shared segment boundaries across layers |
| `pipeline/segment.go` | streaming segment execution with atomic writes |
| `pipeline/sync.go` | end-to-end A/V sync check against the 40 ms tolerance |
| `rtp/recover.go` | windowed sequence reassembly and gap reporting |
| `manifest/write.go` | deterministic segment manifest |
| `checkpoint/state.go` | resumable progress bound to input and parameters |
| `trace/provenance.go` | per-segment input/output provenance |
| `fixtures/` | deterministic MP4/MOV and RTP generators |
| `runner/` | batch orchestration |
| `cmd/verify/` | terminal entry point |

## Time handling

Track ticks convert to media time with exact 128-bit integer arithmetic and
round-half-away-from-zero; floating point is never used to accumulate a
timeline. Non-monotonic presentation times, 32-bit wraparound and large sample
gaps are classified and reported, never silently reordered.

## Determinism and limits

- Identical inputs and parameters produce byte-identical segments and the same
  manifest digest, whether or not the run was interrupted and resumed.
- Completed segments are committed to the checkpoint only after the file and
  its digest are on disk; loaded checkpoints drop entries whose files vanished
  or whose bytes changed.
- Per-input limits bound input size, sample count and duration; a segment that
  would exceed the byte cap fails rather than growing without limit.
- Output paths are sanitized and confined to the work directory; temp files use
  atomic rename and never appear in manifests.
