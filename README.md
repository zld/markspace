# mediarc

A reusable Go media-processing kernel for long-term media archives. It puts
subtitles, RTP audio and MP4 containers on one nanosecond timeline, recovers what
is still readable from damaged inputs, and quantifies how well the recovered
timeline lines up.

Everything runs locally on macOS (Darwin) from a terminal. There is no network
access, no external media and no graphical output: all fixtures are generated by
code.

## Quick start

```sh
go mod tidy
go build ./...
go test ./...
go run ./cmd/mediarc demo --seed 7 --window 4 --max-buffer 8
```

The demo writes fixtures and a review manifest under `./out` (override with
`--out`). It prints frame and segment hashes, pixel mean, loudness peak, packet
loss and recovery counts, the first unreadable byte offset and the maximum
alignment error.

Exit codes: `0` success, `1` a sample assertion failed, `2` bad parameters.

## Layout

| Path | Role |
| --- | --- |
| `model/error.go` | One error type with stable codes and fatal/recoverable severity |
| `timebase/timecode.go` | 24 / 25 / 29.97 DF / 29.97 NDF / 50 fps ↔ int64 nanoseconds |
| `subtitle/srt.go`, `subtitle/vtt.go` | Recovering SRT and WebVTT parsers |
| `rtp/window.go` | Bounded jitter window: wraparound, reordering, duplicates, gaps |
| `rtp/recover.go` | Turns gaps into silence segments of exactly the missing duration |
| `container/scan.go`, `container/scan_index.go` | MP4 index validation, truncation scan, box resync |
| `sync/align.go` | Cue ↔ anchor alignment with a hard tolerance |
| `stream/pipeline.go` | Bounded, cancelable pipeline with backpressure |
| `render/render.go`, `render/metrics.go` | Deterministic off-screen frames/audio and statistics |
| `sample/generate.go` | Fixture generator used by the demo and its tests |
| `demo/run.go` | The acceptance scenario |
| `cmd/mediarc/main.go` | Terminal entry point |

## Behaviour worth knowing

**One timeline.** Frame labels, subtitle clocks, MP4 sample times and RTP
timestamps all convert into `int64` nanoseconds with exact integer arithmetic and
round-half-up. Conversions that would leave `int64`, or go negative, return a
stable error instead of wrapping.

**Drop-frame is checked, not assumed.** `00:01:00:00` at 29.97 DF names a label
the clock never emits and is rejected with `illegal_drop_frame`; every tenth
minute is exempt, as the standard requires.

**Parsing recovers.** A malformed SRT/VTT block yields an `invalid_cue` error
carrying its byte offset, and scanning resumes at the next cue candidate. Every
recovered cue keeps its source line numbers and byte offsets, so text can be
quoted straight back out of the input.

**RTP time is media time.** Frames are placed from their RTP timestamps, not
arrival times, so a clock discontinuity is reported as `timestamp_jump` rather
than silently absorbed. Duplicate packets are idempotent under a bounded
delivered-sequence history, out-of-order packets are re-inserted, and 16-bit
sequence wraparound is unwrapped. A gap becomes a silence segment covering
exactly the missing packet duration, so later cues do not shift.

**The index is never trusted blindly.** Chunk offsets, sizes and durations are
checked against the real file length. A chunk that leaves the file is dropped and
reported while other readable chunks still expand. With no usable index the
scanner resynchronises on the next plausible box header and turns readable `mdat`
bodies into synthetic samples. The first unreadable offset is always clamped
inside the input.

**Alignment reports, never moves.** Cues pair with their nearest anchor and the
signed error is recorded. Anything beyond the tolerance (1 ms by default) is
flagged `alignment_drift` with the cue's own timestamp untouched.

**Rendering is reproducible.** Frames derive their colour and marker from the slot
position; media audio is a parametric sine and recovered regions are silence.
Re-running the demo produces byte-identical hashes.

**Memory is bounded.** Every pipeline queue has the same configurable capacity,
and the jitter window's resident set is capped by its depth. A slow consumer
blocks its producer instead of growing without limit.

## Note on the Go version

The brief asks for Go 1.23, but the pinned `github.com/pion/rtp v1.10.6` declares
`go 1.24.0` in its own `go.mod`, so Go refuses to build this module below 1.24.
`go.mod` therefore states `go 1.24.0`: the lowest version that satisfies the
pinned dependency set. The kernel code itself stays within the Go 1.23 language
surface.

## Dependencies

* `github.com/abema/go-mp4 v1.7.4` — MP4 box headers and sample tables
* `github.com/pion/rtp v1.10.6` — RTP packet parsing

Both are pinned in `go.mod` and `go.sum`; `go mod tidy` adds nothing else.
