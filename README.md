# assetcheck

Offline media delivery validation and manifest migration for multi-language game
dialogue, subtitles and effects. Every command runs locally, reads files in
bounded chunks, and reports the raw input byte offset of anything it rejects so
a failure can be traced back to the exact bytes.

## Requirements

- macOS (Darwin) with the Go toolchain. Install with `brew install go`.
- Go 1.23 or newer (`go.mod` declares `go 1.23`).
- No network services, no media codecs, no external assets. Fixtures are
  generated by the tool itself.

## Dependencies

`go.mod` pins the requested versions:

| Module | Requested | Resolved |
| --- | --- | --- |
| `github.com/abema/go-mp4` | `v1.0.4` | `v1.0.0` via `replace` |
| `github.com/pion/rtp` | `v1.8.9` | `v1.8.9` |

**Note on go-mp4:** upstream never published a `v1.0.4` tag — the release line
goes `v1.0.0` straight to `v1.1.0` (both `proxy.golang.org` and `goproxy.cn`
return 404 for `v1.0.4`). The `require` keeps `v1.0.4` as asked and a documented
`replace` resolves it to `v1.0.0`, the nearest available `v1.0.x`, which exposes
the same container and time-base API (`BoxInfo`, `Mvhd`, `Tkhd`, `Mdhd`, `Stts`)
used by `internal/mp4index`. `go mod tidy` leaves `go.mod` unchanged.

## Build and test

```sh
go mod tidy
go build ./...
go test ./...
```

`go test ./...` runs the unit tests for every subsystem plus the acceptance
tests for the CLI (`cmd/assetcheck`).

## Acceptance walkthrough

```sh
go run ./cmd/assetcheck demo --seed 17 --out /tmp/game-assets
go run ./cmd/assetcheck verify --input /tmp/game-assets/valid.mkv
go run ./cmd/assetcheck verify --input /tmp/game-assets/truncated.mkv
go run ./cmd/assetcheck migrate --input /tmp/game-assets/valid.mkv \
  --manifest /tmp/game-assets/manifest-v1.json --out /tmp/game-assets/out \
  --stop-after normalize
go run ./cmd/assetcheck migrate --input /tmp/game-assets/valid.mkv \
  --manifest /tmp/game-assets/manifest-v1.json --out /tmp/game-assets/out --resume
```

What each command proves:

- **demo** writes nine fixtures plus `expectations.json`. The same seed writes
  byte-identical files. The damaged fixtures list the element ID and byte offset
  the validator must report.
- **verify (valid)** prints element count, track count, fragment count, the
  maximum cross-track deviation (at most 1 ms) and the file SHA-256. Repeating it
  prints the same hash.
- **verify (truncated)** prints the failure category, element ID, first offset
  and `offset-delta: 0 bytes` against the generator preset.
- **migrate --stop-after normalize** stages two checkpoints and publishes
  nothing (`result: STAGED`).
- **migrate --resume** reuses the verified checkpoints, reports the resume stage,
  elapsed milliseconds, the reason and the final SHA-256. That hash equals the
  one from an uninterrupted run.

## Exit codes

| Code | Meaning |
| --- | --- |
| 0 | verification or migration succeeded |
| 2 | input corrupt or specification violated |
| 3 | checkpoint mismatch |
| 4 | local read/write failure |

## Layout

| Path | Responsibility |
| --- | --- |
| `internal/ebml` | Chunked Matroska reader, raw offsets, unknown-length boundaries |
| `internal/timeline` | Shared nanosecond time base and structured error model |
| `internal/tracks` | Channel layout, sampling rate and colour validation |
| `internal/fragments` | Fragment timing, cross-track deviation, sequence and order |
| `internal/media` | Container-neutral asset model |
| `internal/matroska` | EBML tree adapter |
| `internal/mp4index` | MP4 sidecar adapter (go-mp4) |
| `internal/rtpcheck` | RTP capture validation (pion/rtp) |
| `internal/manifest` | Versioned schema and old/new field adapters |
| `internal/migrate` | Parse/normalize/write stages, checkpoints, atomic commit |
| `internal/pipeline` | Composition of the above |
| `cmd/assetcheck` | Terminal entry point |
| `testdata` | Fixture generator |

## Guarantees

- Unknown-length EBML masters close only at a legal parent boundary.
- An element ID, failure category and input byte offset are reported together.
- Cross-track deviation must stay within 1 ms.
- Unknown manifest versions and unmappable fields stop migration with the JSON
  path; no field is dropped silently.
- The same inputs produce the same output SHA-256, with or without a resume.
- A failed write never replaces the last committed generation.
