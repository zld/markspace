# mp4flow

A from-scratch, dependency-free (no FFmpeg) C++17 tool for game-release build
pipelines that ingest fragmented MP4 (fMP4) shards produced by different
recording and encoding jobs. It checks initialization-segment compatibility,
reorders fragments, rebuilds a continuous per-track timeline, repacks each
`moof` into its own output fragment, and re-verifies the published package.

All sample data is synthetic and generated by code; no external media files
are referenced and nothing is transcoded. Only local, unencrypted fMP4 is
handled.

## Layout

| Path | Responsibility |
| --- | --- |
| `include/box_reader.hpp`, `src/box_reader.cpp` | Bounded recursive box parser (32-bit, 64-bit `largesize`, zero-to-end sizes), big-endian cursor, overflow checks |
| `src/init_compat.cpp` | Extracts and compares track id, handler, timescale, sample entry and `trex` defaults; rejects encrypted entries |
| `include/box_writer.hpp`, `src/box_writer.cpp` | Size-patching big-endian box writer shared by fixtures and the repacker |
| `include/fragment_index.hpp`, `src/fragment_index.cpp` | Per-file/per-moof index: `mfhd`, `tfhd`, `tfdt` v0/v1, `trun` v0/v1, sample counts/durations, mdat ranges, sequence conflicts |
| `src/repack.cpp` | Splits multi-`moof` files, renumbers `mfhd`, rebases `tfdt`, rebuilds `trun` data offsets, stages + atomically publishes |
| `src/validator.cpp` | Re-runs the index pipeline and the expected-sequence range check |
| `src/cli.cpp`, `src/main.cpp` | Terminal interface and exit codes |
| `src/fixture_builder.cpp` | Code-generated `valid` / `gap` / `bad-init` / `encrypted` fixtures |
| `tests/` | Catch2 3.x parser unit tests and end-to-end pipeline tests |

## Build and test

```sh
brew install cmake catch2
cmake -S . -B build -DCMAKE_PREFIX_PATH="$(brew --prefix catch2)" -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
ctest --test-dir build --output-on-failure
```

## Usage

```sh
# Generate a synthetic workspace.
./build/mp4flow fixtures --work /tmp/fmp4-demo --case valid

# Repack: 4 input files / 5 moofs -> 5 output fragments, continuous seq 1..5.
./build/mp4flow repack --init-dir /tmp/fmp4-demo/init \
  --media-dir /tmp/fmp4-demo/media --out /tmp/fmp4-demo/out \
  --expect-seq 101:105 --max-correction-ms 3000

# Verify and print any missing expected sequence.
./build/mp4flow verify --init-dir /tmp/fmp4-gap/init \
  --media-dir /tmp/fmp4-gap/media --expect-seq 101:105
```

A wrapper that runs the full acceptance flow lives in `scripts/demo.sh`.

### Exit codes

| Code | Meaning |
| --- | --- |
| 0 | success |
| 2 | initialization segments incompatible (or encrypted) |
| 3 | invalid box structure or sample layout |
| 4 | one or more expected `moof` sequences missing |
| 5 | read/write or atomic-publish failure |

Errors report the offending file, the box path (for example
`moof/traf/trun`) and the reason.

## Correctness notes

* Sample duration/size resolve with `trun` > `tfhd` default > `trex` default.
* Composition offsets honor `trun` version 0 (unsigned) and version 1
  (signed); `tfdt` similarly supports versions 0 and 1.
* Every rebuilt `trun` data offset is recomputed relative to its new `moof`,
  and each sample range is re-checked against its paired `mdat`.
* Output is written to a sibling staging directory, fully re-parsed through
  the same index/validation code, and only then renamed into place; staging
  is removed on any failure.
* File size, offset and time arithmetic use checked additions and reject
  32-bit/64-bit overflow.
