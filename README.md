# mediaregress

A local media processing kernel for MXF/MP4 tracks. It parses container
metadata, builds one integer timeline, cuts segments at sample boundaries,
detects silence, fingerprints content and records a resumable, verifiable
manifest. Everything runs locally against synthetic fixtures generated by the
Go test code; no external service or media file is involved.

## Requirements

- macOS (Darwin) with Go 1.23 or newer (`brew install go`)
- Dependencies are pinned in `go.mod`:
  - `github.com/abema/go-mp4 v1.3.0` for MP4 box and track timing
  - `github.com/pion/rtp v1.8.9` for RTP header parsing and sequence checks

## Build and test

```
go mod tidy
go build ./...
go test ./...
```

## Commands

```
go run ./cmd/regress generate --dir ./tmp/fixtures
go run ./cmd/regress run      --input ./tmp/fixtures/valid.mp4 --checkpoint ./tmp/state --output ./tmp/result.json
go run ./cmd/regress verify   --input ./tmp/fixtures/valid.mp4 --checkpoint ./tmp/state --output ./tmp/result.json
go run ./cmd/regress run      --input ./tmp/fixtures/damaged.mp4 --checkpoint ./tmp/bad-state --output ./tmp/bad.json
go run ./cmd/regress resume   --input ./tmp/fixtures/valid.mp4 --checkpoint ./tmp/interrupted-state --output ./tmp/resumed.json
```

`generate` writes:

| file | purpose |
| --- | --- |
| `valid.mp4` | rotation, crop, two conflicting `nclx` color descriptions, audio with silence |
| `badcrop.mp4` | clean aperture wider than the frame; that track is rejected |
| `damaged.mp4` | truncated `stco` box |
| `boundary.mp4` | 60 fps video for boundary-ownership checks |
| `duplicates.mp4` | repeated content so segments deduplicate |
| `valid.mxf` | KLV metadata sets and essence |
| `conflict.mxf` | two picture descriptors with conflicting color properties |
| `damaged.mxf` | essence element clipped past end of file |

`run` prints `tracks`, `segments`, `silence_ranges`, `duplicates` and
`output_sha256`. For damaged input it prints `error_track`, `error_offset`,
`error_class` and `error_stage`, with the offset at the first missing byte.

`resume` prints `resumed_segments`, `reused_segments`, `resume_ms` and
`output_sha256`. When the checkpoint directory has no completed work it first
performs a simulated interrupted pass, so resume is always meaningful and its
hash matches an uninterrupted run.

`verify` recomputes the manifest digest, the provenance seal and the content
digest, and checks the checkpoint's recorded output digest.

Exit codes: `0` success, `2` damaged input with a positioned error, `3`
checkpoint or output verification failure. Note that `go run` maps a non-zero
exit from the program to shell status 1; build the binary
(`go build -o regress ./cmd/regress`) to observe 2 and 3 directly.

## Layout

```
cmd/regress            terminal entry point
internal/media         nanosecond Ticks scale, structured errors, digests
internal/track         MP4/MXF parsers, track model, dependency graph
internal/timeline      per-track timelines merged on the shared scale
internal/split         sample-boundary segmentation
internal/silence       absolute-window silence detection over RTP audio
internal/fingerprint   content digests, incomplete marking, dedup groups
internal/checkpoint    atomic resumable state with selective invalidation
internal/provenance    sealed input/stage/output record
internal/engine        stage orchestration, manifest sealing, verification
internal/fixture       deterministic MXF/MP4 fixture writers
```

## Guarantees

- Times are integer nanoseconds throughout; conversions floor exactly once and
  duration is derived from cumulative decode times, so long tracks do not drift.
- Raw rotation matrices, crop rectangles and color descriptions are preserved
  beside their decoded values with container, element and byte offset.
  Conflicting color descriptions are recorded, never silently resolved.
- Segment windows are half-open, so a sample on a cut boundary belongs to
  exactly one segment.
- Silence windows are anchored to absolute multiples of the window length; a
  window crossing a segment cut is evaluated once and lists both segments.
- A segment shorter than one comparison window is marked `incomplete` and is
  never reported as a duplicate, however identical its bytes are.
- Checkpoints save atomically and record stage, input digest, completed
  intervals and output digest. A changed track digest invalidates only that
  track's indexes and downstream results.
- The manifest is deterministic: slices are sorted, no maps are serialised and
  timing is excluded, so reruns and resumes of the same input and options
  produce byte-identical documents.
- Damaged input never masquerades as a complete manifest: the document is
  written with `complete: false`, and only the readable prefix is indexed.
- File access is streaming with bounded buffers; memory follows the processing
  window, not the file size.
