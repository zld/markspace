# Media repair and release toolkit

Offline Go 1.23.12 project for validating image-frame manifests, repairing
media timestamps, building checksummed random-access indexes, resumable
four-frame checkpoints, probe metrics, and atomic multi-platform package
release/rollback.

Dependencies are pinned in `go.mod`:

- `github.com/abema/go-mp4 v1.7.4`
- `github.com/pion/rtp v1.9.0`

All sample PNG frames, PCM WAV beats, manifests, RTP fixtures, and minimal
MP4 sample tables are generated by code under `internal/testfixture`; no
external media or network service is required.

## Acceptance

```sh
go mod tidy
go mod download
go build ./...
go test ./...
go run ./cmd/verify -scenario all -root .tmp/acceptance -checkpoint-frames 4
```

The aggregate scenario generates 12 16×16 PNG frames and a 48 kHz WAV beat
reference, then covers bad checksums, truncated MP4 data, RTP half-period
wraparound ambiguity, same-path content replacement, metadata-only changes,
packaging-cache invalidation, rollback, interruption, and resume.

Recovery:

```sh
go run ./cmd/verify -scenario interrupt -after-block 1 -root .tmp/recovery
go run ./cmd/verify -scenario resume -root .tmp/recovery
```

The verify application returns `75` for the simulated interruption. The
standard `go run` driver reports every nonzero child exit as its own status
`1` while printing `exit status 75`; build `./cmd/verify` first when a shell
must observe the exact application status. `scripts/acceptance.sh` does this
and asserts statuses `75` and `0` from the compiled binary.

Application exit codes are:

- `0`: success
- `2`: bad arguments or acceptance-result mismatch
- `3`: input or filesystem/write failure
- `75`: resumable interruption marker

## Layout

- `internal/media`: rational time bases and structured errors
- `internal/source`: manifests, PNG/JPEG decoding, MP4 sample tables
- `internal/cache`: content, packaging, metadata fingerprints and counters
- `internal/repair`: monotonic timestamp repair and RTP expansion
- `internal/index`: checksummed blocks and time lookup
- `internal/batch`: streaming blocks, staging, checkpoints, resume
- `internal/rollback`: platform version directories and current pointers
- `internal/probe`: RGB, WAV loudness, onset/alignment metrics
- `internal/acceptance`: terminal scenarios and assertions
- `cmd/verify`: CLI entry point
- `scripts`: fixture and acceptance helpers
