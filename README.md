# lutgrade

Terminal tool for deterministic LUT grading of level screenshots and
cutscene keyframes. It applies Adobe `.cube` 3D LUTs to binary P6 PPM
images, with explicit sRGB / Display-P3 color handling, trilinear and
tetrahedral interpolation, and serial-vs-parallel pixel verification.

No third-party image or LUT libraries are used: the `.cube` and PPM
formats are parsed in-tree, and all sample material is generated by the
tool itself.

## Requirements

- macOS 13+ (Darwin) with Apple Clang
- CMake 3.29 or newer

```sh
xcode-select --install
brew install cmake
```

## Build and test

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
ctest --test-dir build --output-on-failure
```

The full acceptance flow (build, tests, fixtures, graded render and a
determinism check) is one script:

```sh
zsh scripts/demo.sh
```

## Commands

### Generate fixtures

```sh
./build/lutgrade fixture --dir build/demo --width 96 --height 64 --grid 17
```

Writes `input.ppm` (16-bit gradient), `patches.ppm` (boundary color
blocks) and `look.cube` (a smooth in-range grading LUT). Everything is
derived from the parameters, so reruns produce byte-identical files.

### Render

```sh
./build/lutgrade render \
    --input build/demo/input.ppm \
    --lut build/demo/look.cube \
    --input-space srgb \
    --lut-space display-p3 \
    --output-space srgb \
    --interpolation tetrahedral \
    --path compare \
    --threads 4 \
    --output build/demo/graded.ppm
```

Per pixel the tool: decodes the input transfer curve, converts linear
RGB into the LUT color space via XYZ, normalizes against the LUT domain,
samples the shared interpolation kernel, converts into the output color
space, and re-encodes. `--path compare` additionally renders the serial
reference and the threaded schedule and prints `max_dev_r/g/b`.

### Options

| Option | Values |
| --- | --- |
| `--input-space`, `--lut-space`, `--output-space` | `srgb`, `display-p3` |
| `--interpolation` | `trilinear`, `tetrahedral` |
| `--out-of-bounds` | `clamp` (default, counted), `error` |
| `--path` | `single` (default), `compare` |
| `--threads` | 1–256 (1 selects the serial path) |
| `--grid` (fixture) | 2–65 |
| image dimensions | 1–32767 per axis |

## Output and numeric evidence

Each render prints the LUT grid size, pixel count, thread count,
out-of-domain clamp count, and six 16-bucket histograms
(`histogram_before_*` for values entering the LUT, `histogram_after_*`
for encoded output). Every channel histogram sums to the pixel count.

## Exit codes

| Code | Meaning |
| --- | --- |
| 0 | success |
| 2 | invalid command line arguments |
| 3 | malformed or semantically invalid file content |
| 4 | file read/write failure |
| 5 | rendering failure (bad pixels, worker error, OOB error) |

Output files are written to a same-directory temporary file, fsynced,
then atomically renamed; a failed render never leaves a complete file at
the target path.

## Layout

```
include/grade/   public headers (cli, color, cube_lut, image_ppm, render, fixture)
src/             module implementations and main entry point
tests/           dependency-free test suites (pipeline, render, e2e)
scripts/demo.sh  one-command acceptance flow
```

## Design notes

- Serial and chunked-parallel schedules call the same stateless
  interpolation kernel on disjoint row ranges; with identical inputs and
  interpolation the reported deviation is exactly `0.000000`.
- Both supported spaces use the sRGB transfer curve; they differ in their
  D65 linear-RGB↔XYZ matrices. Matrix inversion rejects non-finite or
  singular matrices.
- `.cube` errors name the 1-based line and reject duplicate directives,
  non-finite numbers, entry-count mismatches, invalid domains and grids
  outside 2–65.
- Paths containing `..` segments are rejected, integer dimensions are
  range-checked before multiplication, and raster sizing is checked for
  overflow.
