# mediasync

Offline media/subtitle alignment kernel. It analyses MP4 sample tables, RTP
timestamps and SRT/WebVTT cues on one 90 kHz time base, merges them through an
event-time watermark, and reports drift, damaged byte ranges and stable
SHA-256 digests.

No decoding, playback, network access or external services are involved. All
fixtures are generated by Go code at run time.

## Requirements

- macOS (Darwin), local terminal only
- Go 1.23 (`brew install go@1.23`)
- Pinned dependencies: `github.com/abema/go-mp4 v1.4.1`,
  `github.com/pion/rtp v1.8.11`

## Acceptance

```sh
export PATH="$(brew --prefix go@1.23)/bin:$PATH"
go mod tidy
go build ./...
go test ./...
go run ./cmd/mediasync demo --seed 7 --late-window 2s
```

The demo generates and analyses nine samples: a normal take, a truncated MP4,
a corrupted RTP recording, an illegal drop-frame timecode list, in-window and
out-of-window late subtitle events, an SRT with invalid times/negative
duration/overlap, a VFR MP4, and an RTP recording crossing the 32-bit
timestamp wrap. It prints, per sample: input names,
cue/keyframe/packet mapping, keyframe count and actual-time intervals, maximum
time and byte deviation, damaged byte ranges, error categories, the first
failure position and the SHA-256 digest.

Exit codes:

| code | meaning |
| ---- | ------- |
| 0 | every acceptance rule passed (the demo's deliberately damaged samples reported their errors correctly) |
| 1 | a `check` run found material errors and reported them |
| 2 | invalid arguments or an execution failure |

`demo` exits 0 when the cross-sample acceptance relations hold — the normal
sample deviates by at most one tick, both damaged samples report a
byte-localised first failure, the invalid SRT reports every problem with its
source line, VFR intervals differ by actual time, the RTP wrap expands without
spurious errors, the in-window late event recomputes to the event-time baseline
digest, and the out-of-window event is reported as unrecoverable with its
source line. `check` follows the material-error
semantics for real inputs.

## Commands

```sh
# Full demo
go run ./cmd/mediasync demo --seed 7 --late-window 2s

# Analyse local inputs (any subset of flags)
go run ./cmd/mediasync check --mp4 a.mp4 --srt a.srt --vtt a.vtt \
    --rtp a.rtp --timecode tc.txt --late-window 2s

# Digest only, for baseline comparison
go run ./cmd/mediasync digest --mp4 a.mp4 --srt a.srt
```

Input formats for RTP and timecode files are simple synthetic containers
generated by `internal/fixtures`; they are documented in the package comments.
MP4 and SRT/VTT are parsed as standard containers/text.

## Design

```
internal/clock      90 kHz ticks, timecodes, unwrapping, watermark, drift
internal/subtitle   SRT and WebVTT parsing with source lines
internal/stream     MP4 boxes/sample tables and RTP packet records
internal/timeline   event-time merge with sealed prefix + replayable tail
internal/validate   cross-module rules, cue mapping, drift, damaged ranges
internal/report     deterministic rendering and SHA-256 digests
internal/issue      shared error model (category + line/byte/packet position)
internal/fixtures   deterministic MP4/RTP fixture writers
```

Key rules:

- **One time base.** All timestamps are converted to 1/90000 s. 24, 25,
  29.97 (1001/30000) and 50 fps frame durations divide this base exactly, so
  timecode conversion error is 0 ticks (the contract allows 1).
- **Drop-frame.** `HH:MM:SS;FF` is accepted only at 29.97. Skipped frame
  numbers at the start of minutes (other than every tenth minute) are rejected
  with the source line, never repaired.
- **Watermark.** Events advance `horizon = maxSeen - lateWindow`. A sealed
  prefix (times below the horizon) is never rewritten. A late event inside the
  window is inserted into the replayable tail and triggers recomputation of
  every adjacency up to the previous frontier. An event below the horizon is
  reported as `late_event_unrecoverable` with the horizon at admission and the
  cue/byte/packet position. The final sequence is the sealed prefix followed by
  a canonical sort, so replaying the same arrivals always yields the same
  digest.
- **Unwrapping.** RTP 32-bit timestamps and MP4 decode-time series are expanded
  separately. Duplicates, regressions and missing sequence numbers enter the
  shared issue model with byte/packet positions.
- **Drift.** Least-squares offset is bounded at 100 ms per 10 minutes of
  elapsed time. When exceeded the run reports it and keeps every original
  timestamp unchanged.
- **VFR.** Keyframe intervals come from actual decode times. A varying `stts`
  delta marks the track as VFR; a nominal frame rate is never substituted.
- **Damage.** Structural scanning localises the first incomplete box at the
  exact byte where the file stops making sense (e.g. the `stsz` header).
  Corrupt or truncated RTP records point at the record/header byte. Adjacent
  ranges (gap ≤ 4 bytes) are merged into damaged regions.
- **Stable output.** Digests are computed from normalized canonical content
  only: no wall-clock time, temporary paths, map iteration order or randomness.
  Arrival-order counters are excluded so an in-window replay matches its
  event-time baseline.

## Memory

RTP records are streamed one at a time; the parser retains only per-packet
metadata. A regression test (`TestRTPMemoryBound`) checks peak heap growth
stays below 2× the input size, which is the contract target for 1 GB inputs.
