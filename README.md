# archive

A terminal-only Go media processing core for long-term archive work: it
demuxes MXF and MP4 subsets, maps tracks across containers, recovers data
from damaged or under-indexed files, remuxes without re-encoding, resumes
after interruption, and verifies the result.

All sample MXF/MP4 data and their damaged copies are generated by the
project itself, so nothing binary is checked in and every run is
reproducible.

## Requirements

- Go 1.23 (module pins `github.com/abema/go-mp4 v1.3.0` and
  `github.com/pion/rtp v1.8.9`)
- local macOS/Darwin terminal, no external services

## Build, test, demo

```sh
go mod tidy
go build ./...
go test ./...
go run ./cmd/archive demo --format mixed --corrupt truncate,segment,index --checkpoint /tmp/archive.ckpt
```

The demo writes generated inputs and `restored.mp4` under `demo-out/`
(override with `--out`). Add `--interrupt` to simulate a mid-run stop and
resume from the checkpoint. Exit codes:

| code | meaning |
|------|---------|
| 0 | every check passed |
| 1 | input damaged and part of it is unrecoverable |
| 2 | verification or argument error |

## Data flow

```
fixture ──► probe ──► track graph + explicit timeline
                │
                ├─ recovery scan (when index missing/unusable)
                ▼
            demux ──► maptrack (dependency order, colour arbitration)
                │
                ▼
            remux (lossless, shared-timeline commit gate) ──► verify
                │
                └────────────► checkpoint (digest-bound resume)
```

### Packages

- `internal/model` – unified nanosecond timeline, integer timebases, track
  and dependency graph (cycle detection).
- `internal/fault` – one error record: code, byte offset, track, nanosecond
  range.
- `internal/essence` – self-describing elementary frames with CRC, optional
  embedded RTP header (`pion/rtp`) used as a second clock.
- `internal/fixture` – deterministic MXF/MP4 generation and damage injection
  (truncate, segment, length, index).
- `internal/probe` – defensive MP4 box and MXF KLV parsing into the model.
- `internal/demux` – boundary-exact payload extraction; validates every frame.
- `internal/recover` – frame resynchronisation, exact boundary timing,
  unrecovered interval reporting.
- `internal/maptrack` – joins container versions by logical identity,
  resolves colour by MXF > MP4 > default while keeping every claim.
- `internal/remux` – verbatim payload copy into a faststart MP4; parallel
  workers commit through the shared timeline.
- `internal/checkpoint` – atomic, digest-bound resume state.
- `internal/verify` – black-box re-probe/re-demux comparison of hashes,
  counts and ranges.
- `internal/pipeline`, `cmd/archive` – orchestration and CLI.

## Design decisions

- **No re-encoding.** Remux copies essence bytes unchanged; verification
  compares SHA-256 per packet before and after.
- **Explicit, not implicit, gaps.** Frames that cannot be validated are
  reported with their offset and time range and marked unrecoverable; the
  remux preserves absolute timing across skipped frames rather than sliding
  later frames earlier.
- **Index is not trusted blindly.** Every index entry is re-validated
  against the bytes it points at; a lying or incomplete index falls back to
  scanning.
- **Determinism.** Fixtures, mapping order, fault ordering and output bytes
  are pure functions of the inputs, so reruns produce identical checksums.
- **Colour conflicts are data.** Arbitration picks a winner by source
  priority but retains every disagreeing value and its source for audit.
