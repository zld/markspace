# matroska_mp4 — H.264/AAC Matroska → MP4 remuxer

A self-contained remuxer for build-pipeline media: it copies compressed
H.264 and AAC frames byte-for-byte from Matroska into MP4. There is no
FFmpeg, no external demuxer, and no re-encoding.

## Requirements

- macOS / Python 3.11 (`brew install python@3.11`)
- NumPy 2.4.6 (see `requirements.txt`)

## Setup

```sh
brew install python@3.11
python3.11 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m compileall -q matroska_mp4 tests
```

Never use system `pip`; all commands below run the project interpreter.

## Usage

```sh
# Deterministic fixtures (unknown-size Segment/Cluster, B-frames, all lacing)
.venv/bin/python -m matroska_mp4 fixture --out-dir .tmp/fixtures

# Rewrite: global earliest PTS becomes 0, DTS regenerated, signed ctts
.venv/bin/python -m matroska_mp4 remux \
  --input .tmp/fixtures/reordered.mkv --output .tmp/rewrite.mp4 \
  --mode rewrite --timescale 60000 --report json

# Preserve: per-track PTS must be monotonic; track offsets/gaps kept
.venv/bin/python -m matroska_mp4 remux \
  --input .tmp/fixtures/monotonic.mkv --output .tmp/preserve.mp4 \
  --mode preserve --timescale 60000 --report json

# Tests
.venv/bin/python -m unittest discover -s tests -v
```

`--report text` prints a one-line summary instead of JSON.

### Exit codes

| Code | Meaning |
| ---- | ------- |
| 0 | success |
| 2 | argument error |
| 3 | malformed EBML |
| 4 | unsupported codec, or invalid/unsupported timeline |
| 5 | write or index-audit failure |

Errors are emitted as JSON on stderr with `kind`, `error`, and, for EBML
failures, the byte `offset`.

## How it works

```
CLI → EBML parser → Matroska track/block extraction → shared timeline
    → (preserve | rewrite) → MP4 writer → read-back audit → atomic replace
```

- **`ebml_ids.py` / `ebml.py`** — element IDs and parent/child levels; a
  bounded VINT reader; an element tree that resolves unknown-size `Segment`
  and `Cluster` by the first element outside their child set. Truncation,
  overruns, and illegal VINTs raise `EBMLError` carrying the byte offset.
- **`matroska.py`** — tracks (number, timebase, `DefaultDuration`, avcC, AAC
  ASC), `SimpleBlock`/`BlockGroup`, negative relative timecodes, and all four
  lacing modes (none, Xiph, fixed, EBML) with a size-sum check. Subtitle,
  attachment, and non-H.264/AAC tracks fail with exit 4 — never dropped
  silently. The same applies to features that would change timing or bytes if
  ignored: `ContentEncodings`, `DiscardPadding`, `TrackTimestampScale != 1`,
  `MaxBlockAdditionID`, and dimensions/channels outside the 16-bit MP4
  sample-entry range. `CodecDelay` is accepted: the priming samples stay in
  the media and an initial edit-list trim removes them, as ffmpeg does.
  Blocks are streamed through an EBML presentation hook into compact
  `array.array` indexes, so a 5M-sample input does not keep Python objects per
  frame.
- **`timeline.py`** — NumPy `int64` timebase conversion with overflow
  detection, two rounding modes, duration resolution (BlockDuration →
  DefaultDuration → following interval; the final sample must resolve), signed
  composition offsets, and the preserve/rewrite constraints. Preserve derives
  `stts` from the *rounded* PTS deltas so the sample table and edit list cannot
  drift apart.
- **`export_preserve.py`** — rejects any track whose PTS is not monotonic in
  decode order; keeps per-track offsets via edit lists and leaves gaps intact.
- **`export_rewrite.py`** — regenerates monotonic DTS from block-order sample
  durations, keeps presented PTS, and expresses reordering as a signed
  version-1 `ctts`.
- **`mp4_writer.py`** — `stts`, signed `ctts`, `stsc`, `stsz`, `stss`,
  `stco`/`co64`, version-0/1 headers, 64-bit `mdat`, and edit lists.
- **`mp4_audit.py`** — memory-maps the written file, re-parses the box tree,
  re-expands every sample table with NumPy, and verifies sample counts, track
  mapping, chunk offsets (including cross-track overlap/gaps), `mdat` bounds,
  edit lists, and byte-for-byte frame equality with the source. Only after a
  clean audit is the temporary file `os.replace`d over the target.

## Limits

- Input ≤ 8 GiB, a single frame ≤ 256 MiB, ≤ 5,000,000 samples.
- `--timescale` 1…1,000,000,000; durations must fit `stts`/`ctts` ranges.
- Rewrite keeps the original inter-track offset with an empty edit; it does
  not move audio to compensate for video.

Fixtures are generated by code (`fixture.py`); no external media is read. The
`fixture` command re-reads every generated file and confirms each indexed
frame is reachable, reporting per-fixture frame counts.

## Interop

`ffprobe` is not a dependency, but the generated files were cross-checked
locally: streams, `time_base`, `nb_frames`, start times, and decode-order
DTS/PTS all match (`rewrite`: video DTS 40/80/120/160 ms, PTS 40/120/80/160 ms;
`preserve`: 100 ms start retained).
